# Demo Music Studio 脫敏測試版

這是用於開發、測試和演示的通用脫敏版本，不代表任何真實機構或客戶。

## 運行

- **Windows：雙擊 `serve.cmd`**（推薦）：用倉庫附帶的便攜 Node 起本地伺服器並自動開瀏覽器 `http://127.0.0.1:5500/`。
- **macOS：雙擊 `serve.command`**：有 Node 用 `serve.js`，否則用系統 `python3`（首次可能提示安裝命令列工具）；被 Gatekeeper 擋下時右鍵 → 打開。
- **多人／多裝置使用：把整個資料夾放上靜態網站託管**（GitHub Pages、Cloudflare Pages 等，免費含 HTTPS），把該網址加入 GCP 的 Authorized JavaScript origins，之後任何電腦或手機開網址即可，不需本地伺服器。資料仍是各裝置瀏覽器各自一份，換裝置用「全量備份／還原」搬。
- 或 VS Code 開啟本資料夾 → 右下角「Go Live」（Live Server 擴充，同為 5500 埠）。
- 直接雙擊 `index.html`（`file://`）也能用本地功能，但 **Google OAuth 不支援 file://**，GCal 三個 API 按鈕會用不了；且 `file://` 與 `http://127.0.0.1:5500` 是不同 origin、`localStorage` 資料各自獨立——請固定用同一種方式開啟。

所有資料均為虛構測試資料，只保存於瀏覽器 `localStorage`，不會改動其他版本。

## 脫敏聲明

- 不包含真實學生、導師、電話、電郵、機構名稱或客戶識別資料。
- 測試電郵只使用 `example.com`，電話使用零佔位號碼。
- 不包含地區或真實貨幣標識；金額僅作為無貨幣單位的演示數值。
- 請勿在此目錄放入真實客戶資料，也不要把此版本當作生產資料庫。

## 功能（v2）

- 脫敏學生測試資料（14 人，每導師 5–8 名）和學生 CRUD。情境覆蓋：2 人小組（S003/S004，同時段豁免與 TL 聯動）；樂理 Grade 5 五人小組班 `G01`（Instructor B 週六 15:00）——Student 020/021 同時有自己的一對一課，Student 030–032 只上小組課（`weekday: null`＝沒有個別課）。學生表單用「有常規私教課」勾選框切換：不勾＝只上小組，導師／課程／費率／星期／時間整組隱藏，儲存不查費率、這些欄位留空，學費按所屬小組計；導師篩選（生成勾選區、群發名單）按所屬小組的導師歸類
- **資料模型：學生＝人，報讀項目分兩類。** 個別課掛在學生記錄上（最多一個：星期／時間／時長／課程／級別）；**小組班是獨立實體**（`gac_groups_v2`：名稱／課程／級別／導師／星期／時間／時長／`memberIds`），學生經成員名單加入、可同時屬多個小組。學生名單庫頁籤「+ 新增小組」建立、下方小組班清單「編輯」成員與時段（含撞堂預覽），總課表的小組 chip 上 ✏️ 亦可編輯；學生弹窗也可勾「所屬小組」；學生名單庫每人一行、「常規上課時間」欄列出全部報讀項目（個別＋各小組）。生成時勾學生＝他的個別課、勾小組＝整組（merge 範圍按 groupId 圈定，只勾個別課不會誤刪小組課）；每位成員各自一筆課堂（出席／請假／學費按人），共享 `groupId` 讓課表／日曆／薪酬把同時段當「一節」。學費按人合計、每堂按自身費率查價；薪酬每個報讀項目一行（`學生 @ 小組名`）
- 總課表持久化（`gac_lessons_v2` 按月分桶）；重新生成為 merge 語義，已有狀態不會被清空
- 常規時間／升班調整已併入總課表（原「單一學生」頁籤移除）：學生列表每行 ✏️ 開快速編輯——星期／時間／時長／級別（升班）、「生效月份」保留歷史時間；儲存前**即時預覽**該月與同導師其他課的撞堂（已生成月份按實際課表、未生成月份按各學生常規時間模擬）。保存後到對應月份按「生成」套用；原班際課程的一次性排堂預覽一併移除（資料保留在 `data.js`）
- **費率表驅動的表單**：學生表單的導師級別（資深／普通）→ 課程 → 級別 → 授課形式 → 時長（30／45／60）為連動下拉，只列 `art-rate-data.js` 費率表有定價的組合，上游改動後下游自動修正；每堂學費唯讀、按組合查表自動帶出（不落學生記錄）。快速編輯的級別／時長同樣受限。小組班表單暫維持手動輸入，只加「導師級別（計費用）」。導師級別存於學生／小組的 `tutorLevel`，並隨生成寫入課堂記錄；舊資料缺此欄位時回退示範對應（Instructor B＝資深）。連動／查價邏輯在 `lib/rates.js`
- 課堂狀態機：已排課／已上課／請假（事假 L、病假 SL、導師請假 TL）／NoShow；非法轉換被攔截，批量確認出席
- 請假與補堂兩步解耦：先標記請假，隨時從「待補堂池」（跨月、按等待天數排序）安排補堂；防重複排堂
- 補堂可倒回：還原「已排補堂的請假」會級聯確認並一併取消補堂；請假行內可直接「改期補堂／取消補堂」
- 小組課防護：TL 導師請假全組聯動；補堂時段發散攔截與總表頂部不一致警告橫幅；同一導師時間重疊（撞堂）檢測，小組同時段豁免
- 手動模式：跳過狀態機限制直接改狀態、不觸發小組聯動（每次載入預設關閉，用於修正誤操作）
- 彈窗原則：成功提示一律右下角 toast（3.5 秒淡出，不阻斷）；`confirm` 只留給不可逆或牽連他人的操作（刪除學生／小組／條目、清場與還原、請假與排補堂、取消補堂、級聯取消補堂、整組 TL 請假、批量確認出席、清除排定變更）；`alert` 只用於必填欄位缺漏、系統錯誤與需人工處理的衝突報告。「還原為已排課」「全組出席」「手動模式改狀態」「建立群發」均為可逆，不再彈確認。所有彈窗可點背景或按 Esc 關閉（✕／取消同一路徑）；表單類彈窗（學生／小組／快速編輯／群發／補堂改期）有未儲存改動時先確認「改動會丟失」，儲存路徑不問；同步 GCal 面板執行中不接受背景／Esc 關閉
- 發送中心：學費、請假確認、補堂確認訊息雙欄管理（待發送／已發送，按月獨立；卡片的訊息內文預設收起，只顯示首行摘要與行數，點「訊息」一行展開，頁首「展開全部訊息／收起全部訊息」一鍵切換；「類別」下拉只列本月實際存在的類別，學費另有「未繳清／已繳清」子篩選（母項「學費（全部）」＝兩者都列），自定義群發按訊息名稱列二級子分類——選中即只顯示該批，兩欄計數隨之變動，頁籤紅點徽章仍計全部）；「標記已發」（wa_link）／「手動已發」（manual）／「移回待發」；無電話學生僅可複製或手動已發；學費金額可行內手改（重新生成不覆蓋）。學費卡片走完整個流程：發出後卡片上直接登記繳費（已繳／實收／付款方式／日期／收據，與「出席與繳費」同一筆紀錄；未繳清預設展開、已繳清收起可「修改繳費」），已發送欄標題顯示「N 筆學費未繳清」，「類別」下拉多「學費 · 未繳清／已繳清」子篩選。**催繳與收款確認**（繳費狀態反向驅動發送隊列）：學費單發出滿 N 天（設定，預設 7）仍未繳清（未繳或部分）→ 自動在待發送建「催繳」條目（每生每月一筆，訊息按設定頁模板＋學費條目現值即時組成，部分繳交後未繳金額隨之更新；繳清或學費單移回待發即自動清掉，已發出的留作紀錄；卡片「不用發」可略過）；繳清 → 自動建「收款確認」條目（預設文案「已收妥，謝謝你！確認以上課程。🙋🏻‍♀️」，即在同一個 WhatsApp 對話回的一句；可在訊息模板改，{paid}／{month} 等佔位符仍可用），發出後學費條目的「收據」自動勾上（清除繳費則待發的確認清掉）。繳費表該行的「確認待發」本身就是 WhatsApp 鈕，按了直接開對話發出。兩者的自動開關、天數與文案在設定頁「學費單與繳費」（`lib/sendlog.js` `syncDerived`／`dismissDerived`／`paymentVars`／`fillTemplate`）。點開 WhatsApp 的處理可設定：預設安全模式（標記「已開啟」＋切回頁面時詢問是否已發），可降級為只標記或點開即自動移欄——瀏覽器無法得知訊息在 WhatsApp 裡是否真的送出
- **學費訊息**：按報讀項目逐段列明細（日期 逢星期／時間起訖與時長／級別＝課程＋級別／上課形式（一對一個別授課 Individual、N人小組授課，小組附小組名）／導師／每堂學費／堂數／合共），個別課＋小組課的學生有兩段並加「總額」；明細在生成課表時存入條目（`items`），金額以條目 amount 為準（手改照樣反映）；同一項目內時段不一（某堂經 Calendar 改時）則逐堂列「月/日 時間」。文案在 `app.js` `TUITION_MSG` 常量
- **出席與繳費**（v3）：每位學生一行的月度表，對應學校手工學費表——$/LSN（各報讀項目單價）／LSN／出席・請假・缺席／應收／已發送（＝發送中心狀態，勾＝手動已發、取消＝移回待發；旁有 WhatsApp——未發預填學費單，已發則只打開對話不預填供人手複核）／繳費狀態（**推導而非勾選**：實收 > 0 且已選付款方式才算已繳；只填金額未選方式顯示「未繳 · 待選付款方式」）／備註（**最後一欄，平時只是一個淡便條圖示**，按了才彈出輸入；有備註才顯示文字，留空即刪除。實收金額預設等於應收，要記部分繳交在發送中心的學費卡片「登記繳費」改）／付款方式（編號對應設定頁清單，可增減，預設 現金・轉數快 FPS・銀行轉帳・PayMe・支票）／付款日期（成為已繳時自動補今天）＋橡皮擦鈕清除整筆繳費／學費單預覽（「收據」欄已收起，收款確認訊息發出時仍在條目上記 receipt）；KPI 應收・已收・未收・學費單未發・缺席堂數；導師篩選＋搜尋。繳費欄位掛在 `TUITION` 條目上（`lib/sendlog.js` `setPayment`／`paymentStatus`／`paymentTotals`），發送中心學費卡片同步顯示繳費徽章；「已發送」欄下註「催繳待發／已發」、「收據」欄下註「確認待發／已發」。設定頁「學費單與繳費」：FPS ID／學員守則連結／附註（填了才加到學費單尾段）、付款方式名稱、自動催繳（天數、文案）與收款確認（開關、文案）
- **數據分析**（v3）：按月 KPI——學費應收／已收（出席與繳費）、已上課課值與導師節數・工時（與薪酬同口徑：可計薪＝已上課＋缺席視設定，小組同時段一節）、出席率（已上課÷已上課＋缺席）、缺席率、請假率（÷常規堂）、待補堂、未確認；各導師節數／課值、狀態分佈、各課程堂數四張圖（Chart.js 由 cdnjs 載入，離線退回文字長條）＋各導師明細表。純計算在 `lib/analytics.js`（`monthStats`），頁籤可見時隨資料變動重算
- **歷史記錄與撤銷**（v3）：每個會改資料的操作之前自動拍快照（學生／小組／課表／發送紀錄；設定與薪酬調整不含）——新增／編輯／刪除學生與小組、快速編輯、生成、出席／請假／補堂／取消／改期／手動改狀態、全組操作、批量確認、繳費與學費單狀態、發送中心標記／手改金額／群發／刪除、還原備份、恢復預設、清月／清場、同步 GCal 套用；操作失敗或取消時該筆快照自動丟棄。頂欄「撤銷」／「重做」（原「重置」的位置；撤銷不彈確認，撤銷前的現狀進重做堆疊，重做上限 20、只存記憶體，任何新操作即清空——操作取消／失敗則保留）；原頂欄「重置」（恢復預設學生名單）移到設定 → 危險區。「歷史記錄」頁列出快照（時間、大小）可「還原至此之前」（先自動備份現狀，故可再撤銷）、清空。上限 20 筆，存 `gac_history_v3`，localStorage 配額不足時自動丟最舊；不入全量備份。純函數在 `lib/history.js`
- **導師管理與收費標準表**（v3，設定頁）：導師名單 `gac_tutors_v3`（名稱＋定價等級）驅動排課篩選、學生／小組弹窗、群發與各處導師下拉；選導師時自動帶出「導師級別」（仍可個別改）；刪除導師不改動既有記錄上的名稱（仍會列在下拉）。收費標準表可就地改價（`gac_rate_overrides_v3`，鍵 `等級|課程|級別|形式|時長`），載入時套回 `rateTable`、即時生效於表單查價／薪酬／分析，改過的列標示並可逐列「還原」預設；已生成月份的學費條目要重新「生成」才按新價。兩者都入全量備份與歷史快照
- **設定頁按模組摺疊**（v3）：Google Calendar／學費單與繳費／訊息模板／導師管理／收費標準表／資料備份／一般／危險區，各自收合（開合狀態只存本機 `gac_settings_open`，預設全部收起）；表單類模組各有「儲存設定」，按任一個都儲存全部欄位
- **訊息模板**（設定頁）：學費單開頭／總額／結尾、請假確認、補堂確認、改期通知、催繳、收款確認的文案都可改（`tpl*`／`remindMsg`／`receiptMsg` 設定鍵，留空用預設，每個有「還原預設」）；訊息在顯示時才按模板組成，已建立未發送的條目跟著變，已發送紀錄不受影響。佔位符：課堂類 {date}＝2026年9月16日 {weekday} {time} {name} {id} {tutor} {program} {level}，改期另有 {fromDate} {fromWeekday} {fromTime}；學費單開頭 {month} {m} {name} {id}、總額 {amount}（中段每個報讀項目的明細格式固定）
- **單堂改期**（清單上「已排課」的常規課多一個「改期」鈕）：雙方提前約好把某一堂換時段——課照上，不算請假、不產生補堂鏈，只把該堂的日期時間搬走（跨月自動移桶，lessonId 不變）。小組課整節一起搬（同時段仍是「已排課」的成員），改期前先檢查會不會與同一導師的其他課重疊並要求確認；改期會記下 Calendar 上原本的時段（見下方「本地改期 → Calendar 跟著改」）。完成後自動開「改期通知」訊息彈窗，該課行之後也有「複製改期／WhatsApp」與發送狀態徽章
- **本地改期 → Calendar 跟著改，不另建事件**：補堂改期在本地是「取消舊補堂＋排新補堂」（lessonId 換了），小組課改期連課節 key 也換了——以前同步時舊事件被當殘留刪掉、再推一個新的（或唯讀下舊事件變「手動新建」、新補堂變「Calendar 上沒有」）。現在改期時在課上記 `gcalMovedFrom = { key, date, time, inCal }`（Calendar 上那個事件原本的課節 key 與時段，連改幾次只記第一次；事件 id 交接給新補堂；`lib/gcal.js` `moveSnapshot`／`noteLocalMove`，搬回原時段自動清掉）。同步時 `planLocalMoves` 靠舊 key 或事件 id 認回原事件：**寫入模式**列在「🔁 本地改期 → 改 GCal 上原本那個事件」，勾選＝`events.patch` 該事件（在它所在的那本日曆；新時間、新標題、新標籤，另一種課節型態的標籤設 null），不推新的、不刪舊的、不以 Calendar 為準改回；**唯讀模式**列在「📌 本地已改期、Calendar 上還是舊時間」（附「在 Calendar 打開」連結，只提示），`reconcileByContent` 同樣把舊時段的無標籤事件認作這一堂（`staleMoves`），不當手動新建／Calendar 沒有；導師在 Calendar 改好後再同步，記號自動清掉。唯讀課卡：改期過的課（常規課單堂改期也算——`gcalAddButton` 對常規課只在改期後出現）按鈕是「改 GCal 舊事件（舊 → 新）」，同步記過 `gcalEid` 就直接開該事件的編輯頁、否則開舊時段那一天，並以 8 秒 toast 寫明改成哪個時間（Google 既有事件的編輯頁不能預填）；改期通知彈窗上同一顆鈕（寫入模式是「同步改 GCal 事件」）。按過「加進 GCal」的補堂（記 `gcalAdded`）再改期，硬按「加進 GCal」會先警告重複。另外 `reconcile` 在 key 對不上時會靠成員記著的事件 id 認回（小組在 Calendar 被挪過、收編的手動事件），認回的不再列成手動新建或殘留、也不重推
- **狀態雙向與「以哪邊為準」**：同步時每個已配對的課節都記下 Calendar 事件的 `gcalEid`（`htmlLink` 的 eid，打開編輯頁 `calendar.google.com/calendar/r/eventedit/<eid>` 用）與 Calendar 目前的碼 `gcalCode`。`GACGcal.planStatusSync(pairs, rule)`：只有一邊有資訊 → 流向沒資訊的那邊（Calendar 有碼本地沒有 → 拉回，即原本的「狀態碼變更」；本地標了請假／缺席而 Calendar 沒碼 → **寫回**）；兩邊都有、相同 → 不動；兩邊都有、不同 → 看設定 `gcalConflict`（設定 → Google Calendar「兩邊都改了時以哪邊為準」，`'gcal'` 預設｜`'local'`）。已上課沒有 Calendar 碼：Calendar 沒碼不動，Calendar 有碼且本系統為準 → 清掉碼；小組成員狀態不一時本系統為準表達不了 → 不動。時間也一樣：本地改期過的節 Calendar 又被拖到第三個時間（`planLocalMoves` 的 `conflicts`）→ Calendar 為準交給「時間變更」、本系統為準當改期處理。**寫入模式**：面板「📤 寫回狀態到 GCal」一項勾選＝`events.patch` 該事件，只送 `location` 與 `description`（`statusPatchPayload`：說明欄只換「狀態：」那一行，導師寫的其他內容保留；沒有那一行才整份重寫）。**唯讀模式**：面板「📝 本地標了請假／缺席，Calendar 上還沒有」附「在 Calendar 打開（編輯）」連結；課卡與請假確認彈窗上有「在 GCal 填 狀態：L」（本地碼 ≠ `gcalCode` 時顯示；沒同步過不知道是哪個事件就打開那一天）——Google 只支援預填「新建」事件，既有事件的編輯頁不能預填，碼要自己打。唯讀模式取消補堂：事件已在 Calendar（有 eid／按過加進 GCal／推送過）→ 取消後自動打開該事件讓人刪；寫入模式下次同步列「殘留」
- **補堂事件標題／說明寫明補哪一堂**：標題 `S001 Student 001 補堂([2/5] 09/2026 ← 09/16)`（小組 `樂理 Grade 5 小組 補堂 ×5 (09/2026 ← 09/05)`），說明第二行 `↩ 補的是：2026-09-16（三）15:00 請假的那一堂（09/2026 第 2 節）`（`GACSchedule.originSlot` 從 originLessonId 截取，無需查表）
- **改期通知**（發送中心類型 `MOVE_CONFIRM:<lessonId>`）：單堂改期時建；補堂改期時若舊補堂時間已通知過（補堂確認或改期通知已發）→ 建改期通知而非新的補堂確認；同步 GCal 套用「時間變更」時也建。條目快照改期前的日期時間（`fromDate/fromTime`），改期後讀課堂現值；待發中再改期保留最初 from，已發後再改期重開為待發並以上次已通知時間作 from（`lib/sendlog.js` `ensureMoveEntry`）
- **導師日曆 ID**（設定 → Google Calendar → 導師日曆 ID）：貼整條 embed 網址（`…embed?src=xxx%40group…`）、分享連結（`?cid=…`）或帶 `%40` 的 ID 都會自動整理成 `xxx@group.calendar.google.com`（`GACGcal.normalizeCalendarId`；直接拿 `%40` 去打 API 會被再編碼成 `%2540` → 404）；每位導師旁有「測試」鈕，用目前授權的帳號試讀該日曆，404／403 直接寫出原因。一位導師一個 Google 日曆，填了的導師在同步 GCal 時會逐一讀取各自的日曆並按導師配對（全部留空則只讀預設日曆；有導師沒填則預設日曆也讀）。**推送到誰的日曆**：每節推到該導師的日曆（沒填 ID 的導師 → 預設日曆；`gcalCalendarForTutor`／`gcalPushAcross`），殘留刪除、清空本月／全部清場也逐本日曆做（`gcalListAllCalendars`／`gcalDeleteAcross`）；帶標籤配對上了、但事件放錯日曆的（例如以前推送一律到預設日曆），同步面板列「📦 搬到導師的日曆」，勾選即 `events.move` 搬過去（id 與內容不變）。每堂記 `gcalCalId`＝事件所在日曆。讀取（`listWindow`）帶 `timeZone`＝瀏覽器時區，回傳時間即本地牆鐘，日曆本身的時區設定不影響。存在導師名單 `gac_tutors_v3` 上，入備份與快照。（曾有一個嵌入 Google 日曆的唯讀視圖，因為需要公開日曆或放行第三方 Cookie 才顯示得出來，已移除——總課表的「📅 月曆」視圖已覆蓋其用途）
- **總課表清單的補堂縮排**：補堂節緊接在原請假節之下、縮排並以連接線（└）標示——兩者都在本次清單（月份＋週次＋篩選）內才如此排，否則各自留原位靠「已排補堂 →」「↩ 補 … 的請假課」徽章互指
- **清單列的 WhatsApp 與發送中心聯動**：請假／補堂／改期列上的 WhatsApp 與發送中心是同一條目——點開即按設定標記「已開啟」／切回頁面時詢問／自動已發，列上顯示「待發／已開啟／✓ 已發」；補堂改期過的列（有改期通知條目）改用改期通知文案（「複製改期」）

- **批量確認出席**：按鈕本身就是狀態指示——寫出目前範圍（週次／全月＋導師／學生篩選）內可確認的堂數「批量確認出席（12 堂）」；沒有可確認的就停用，並分辨是「全部已確認出席」還是「無待確認課堂（還有 N 堂未到上課日）」。只會確認今天（含）以前仍是「已排課」的課——未來的課要等上完那天再確認，所以薪酬頁的「待確認」通常大於這個數
- **高級薪酬管理**（2026-09-23 重做）：一句話模型——**預期應付**＝本月排定的課全部上完要付多少，**目前應付**＝已確認出席的課現在要付多少。四個 KPI（目前應付／預期應付／待確認堂數／調整合計）＋進度條，進度條下方把「待確認」拆成「N 堂日期已過但未確認」（要去總課表確認）與「N 堂尚未到上課日」（等上完課自然會確認），下面每位導師一行（已確認／預期堂數、節數、兩個應付金額），點開見每個報讀項目的明細。數字全部由課表算出（`lib/payroll.js` `monthPayroll`：ATTENDED 與 NOSHOW（依設定）＝已確認，SCHEDULED＝待確認，請假不計——其補堂是另一筆課堂記錄），頁面不可手改堂數；唯一能改金額的是「額外津貼／扣款」，每筆可指名導師（計入該導師應付）或選「全月」。「封存本月糧單」把當下的目前應付與各導師金額存成一筆存底。已移除：手動日曆文字解析、讀取公開 ICS（解析結果從來沒有被計算使用）、逐行手改堂數與「隱藏 0 堂學生」、導出薪酬 JSON（全量備份已涵蓋）
- 清單（操作）＋月曆（總覽）兩種視圖（原週曆與逐堂 Google Calendar 預填連結已裁剪——清單按週次過濾＋API 導入完全覆蓋其用途）；清單與月曆可再按導師／學生（或小組班）篩選——兩個下拉聯動：選導師後學生下拉只列名下學生與小組班（`rebuildScheduleFilters`），選學生／小組班後導師下拉自動跟隨（`scheduleFilterTutorOf`）且導師不再限制課堂（該生在別的導師的小組課也看得到）；選某學生時整節小組卡保留以便看到同組成員，月曆略過該生整週沒課的星期（一週一列，`renderMasterCalendarView`），批量確認出席亦只確認篩選範圍內的課（選學生只算該生自己）；月曆色塊可點擊——彈窗內顯示同一張課節卡片（同一套按鈕與流程），操作後月曆即時更新、關閉即回月曆；工具列的篩選下拉以首項作標籤（所有導師／所有學生／全月），標題與視圖切換永不換行；整月 ICS 導出（VEVENT 含 `UID:<lessonId>@guitaristic`）

## Google Calendar 同步（Phase 2）

一次性設置：

1. [GCP Console](https://console.cloud.google.com/) 建專案 → 啟用 **Google Calendar API** → Credentials 建立 **OAuth client ID**（類型 Web application）。
2. Authorized JavaScript origins 加入你開啟本頁的網址。**GIS 不支援 `file://`**，請用本地伺服器（如 VS Code Live Server 的 `http://127.0.0.1:5500`）。
3. 把 Client ID（及目標日曆 ID，預設 `primary`）填入本系統「設定」頁。

使用（總課表頁頂部）：

- **寫入授權開關**（設定 → Google Calendar →「授權寫入 Google Calendar」，**預設關＝唯讀**）：**關＝唯讀模式**——只申請唯讀 scope（`calendar.events.readonly`），同步面板不推送、不清殘留，只把 Calendar 上的改動拉回本地；因為本系統沒寫過標籤，無標籤事件改為**按內容配對**（`lib/gcal.js` `reconcileByContent`：標題以學生 ID 開頭或含學生姓名、含小組名稱；同一學生／小組同一天＝同一節→時間變更／狀態碼；當天沒事件且仍為已排課→「Calendar 上沒有這堂」（只看本月）；Calendar 有而本地沒有→手動新建可收編）。清空本月／全部清場在唯讀模式只清本地。有填「導師日曆 ID」的導師，同步時逐一讀取各自的日曆，**配對不分導師、「Calendar 沒有這堂」只看該導師的課**（事件寫明學號／小組名就配得上，放錯日曆也認得——新建頁預設放主日曆；一本配上的節下一本不再配；沒填日曆 ID 的導師的課在預設日曆；推送則各到該導師自己的日曆）。安全閥：只有在「知道這本日曆屬於哪位導師」（選了導師、或全校只有一位導師）時才判斷「Calendar 上沒有這堂」，否則停用該項並在面板說明——避免把其他導師的課整批誤判成取消。匯入 ICS 未選導師時，會從 .ics 的日曆名稱（X-WR-CALNAME）自動辨認導師。**唯讀模式的日常流程**：出席在系統「批量確認出席」；Calendar「狀態：」留空＝沒資訊，同步不動它、也不寫回（匯入 .ics 後整月留空不會湧出提案）；填了 `A`／「出席」才走「狀態碼變更」拉回出席。本地已上課而 Calendar 卻填了請假／缺席 → `planStatusSync` 標 `conflict`，面板另列「⚠️ 狀態衝突」預設不勾（勾了按「以哪邊為準」：Calendar 為準拉回、本系統為準寫回 `狀態：A`，地點欄留空）；A 與留空視為相同、不互相催填。套用狀態時一律先還原為已排課再標（請假換假別只改 leaveType）；請假可在 Calendar 事件說明欄的「狀態：」一行填 `L`／`SL`／`TL`／`NS`（也接受中文「請假／病假／導師請假／缺席」；地點欄或標題末尾的碼仍可用，說明欄優先），同步時以「狀態碼變更」拉回；補堂可在 Calendar 先建事件（標題以學號開頭或含學生姓名），同步時在「手動新建」選「作為補堂 ←（某次請假）」收編（待補堂池每行「複製標題」「複製內容」給出與推送同格式的標題 `S001 Student 001 補堂([2/5] 09/2026 ← 09/16)` 與說明欄（含「狀態：MU」）——`poolMakeupDraft` 造一個假想補堂交給 `lessonTitle`／`describeLesson`；唯讀「加進 GCal」開新建頁時提示先在「日曆」欄選該導師的日曆；收編時記下事件 id／所在日曆／eid）。反過來，系統裡排的補堂／加課要放進 Calendar，課卡與補堂確認彈窗上有「加進 GCal」——開 Google Calendar 已填好的建立事件頁（標題／時間／地點碼 MU／說明只寫導師），導師選日曆、按儲存，不走 API、不需寫入授權；事件沒有標籤，但唯讀同步按內容配對，下次同步會認得是同一堂。此鈕只在唯讀模式顯示（開了寫入由推送建事件，再建就重複）；**寫入模式**下同一位置（課卡、補堂確認／改期通知彈窗——包括從待補堂池排的補堂）改為「推送到 GCal」（還沒推送過）或「改 GCal 事件」（改期後 Calendar 上還是舊時間），**按下即推這一節、不開面板**（`gcalPushLesson`：有事件 id 就 PATCH 原事件、404 則改為新建；沒有就在導師的日曆 check-then-insert，同標籤已有而本地改期過就改那個）；改期／排補堂後的通知彈窗頂部也問「同步到 Google Calendar 嗎？」一鍵推送。狀態同樣：課卡「寫回 GCal 狀態」直接 PATCH（`gcalPushStatus`，先 GET 只換「狀態：」一行；還沒配對到事件的才開面板）。同步面板的推送候選除本月的課，也包括視窗內（前後 7 天）其他月份的補堂。
- **匯入 ICS**（不用 OAuth）：上傳導師日曆匯出的 .ics（Google 日曆 → 設定 → 該日曆 → 匯出），`lib/ics.js` 解析（行摺疊、UTC／TZID／浮動時間換算、全日、RRULE 每日／每週 BYDAY／每月／每年、INTERVAL／COUNT／UNTIL、EXDATE、RECURRENCE-ID 覆寫、CANCELLED），展開到本月前後 7 天後按內容配對，進同一個面板勾選套用（只改本地）。建議流程：每月先「生成」，再匯入該月的 .ics 作基準；之後日曆有改動再匯入一次，只會列出差異。
- **同步 GCal**（單一入口）：一次授權、一次抓取本月前後各 7 天的事件，兩邊差異分組列在同一面板，勾選後執行——**預設勾選＝執行後兩邊一致，GCal 上的改動以 Calendar 為準**：
  - ⬆️ **推送**：本地有、GCal 沒有 → **一節一個事件**：一對一按 `private.gacLessonId` 查重，標題 `S001 Student 001([1/5] 09/2026)`；小組課同時段全組**只建一個事件**，按 `private.gacCellKey` 查重，標題 `Music Theory Grade 5 小組 ×5 (09/2026)`、description 列成員、`private.gacLessonIds` 存成員清單，事件 id 回填到全體成員。**絕不 update 既有事件**；location 放狀態碼（L/SL/TL/MU/NS，小組全員同碼才寫）。
  - 🕒 **時間變更**／🏷️ **狀態碼變更**：GCal 上被挪動或標了 L/SL/TL/NS → 更新本地（lessonId 不變，跨月自動移桶；小組事件對全體成員生效）。
  - 🗑️ **已刪除**：成員曾回填的事件已不在 GCal → 本地標記請假（一對一事假 L；小組事件被刪＝整堂取消 → 全組導師假 TL）；一次 ≥5 節視為批量清場而非逐堂取消，該組改預設不勾並警告（避免整批誤標請假灌爆待補堂池）。
  - 🧹 **殘留**：標籤對不上任何本地課節（本地改動／重新生成後的舊事件，以及小組課改為一節一事件前推送的逐人舊事件）→ 從 GCal 刪除（垃圾桶可還原；**手動建立的事件永遠不會出現在任何組**）。
  - ➕ **手動新建**：GCal 手動建立、標題可歸屬學生的事件 → 逐條選擇收編為補堂或獨立加課（預設不勾）。
  不做無人值守的自動同步（token 只存記憶體，每次刷新都需重新授權，執行前可全覽差異）。
- **從 data.js 重新載入名單**（設定頁危險區，原「恢復預設學生名單」）：頁面平時只讀 localStorage，換了 `data.js` 要按這個才生效——學生、小組班、導師都重讀並蓋過目前版本（`resetToDefaultData`）；`data.js` 沒有 `defaultTutors` 就從學生／小組的 `tutor`／`tutorLevel` 推出（`GACStorage.tutorsFromRoster`）；已填的導師日曆 ID 按名字保留；課表、發送紀錄、設定不動（舊名單生成的課請「全部清場」再生成）；可撤銷。真實資料的 `data.js` 不要進 git：`git update-index --skip-worktree data.js`。
- **還原演示名單**（設定頁危險區）：`demo_data.js` 存著脫敏演示名單（`demoStudents`／`demoGroups`／`demoTutors`，與 `data.js` 同結構、變數名不同，兩檔同時載入），按一下就換回演示的學生、小組班、導師（`restoreDemoRoster` → 與上面共用 `applyRoster`）；課表不動，要演示課表再「全部清場」→「生成」。導師日曆 ID 按名字記在設定 `tutorCalendarMemo`，演示 ↔ 真實來回切換各自的 ID 自動回填。兩個資料夾若都用 http://127.0.0.1:5500 則共用同一份 localStorage。
- **清空本月／全部清場**（設定頁危險區）：測試點亂後重來。**清空本月**只清總課表目前檢視的月份——該月 GCal 帶標籤事件（含被刪課堂掛連的跨月補堂事件）、本地整月課堂（級聯刪跨月補堂鏈；其他月份請假若其補堂被刪則解鏈回待補池）、該月發送紀錄（含已發送）。**全部清場**刪今天前後一年內所有帶標籤 GCal 事件並清空本地全部月份（課堂／發送紀錄／薪酬調整與封存），完成後另外問是否一併清空歷史快照——不清則快照裡仍保有剛清掉的資料（按「撤銷」可救回），清了才算真正離開本機且無法撤銷。唯讀模式下 Google Calendar 不動，事件下次同步會以「手動新建」出現。學生名單、小組班、導師名單、費率與設定一律保留。兩者都絕不刪 GCal 手動事件（刪掉的可在垃圾桶還原）；本地不可還原，先全量備份。學生名單與設定保留；未設定 GCal 時只清本地。**強制清空 Calendar＋本地（debug）**：清場不碰手動建立的事件，這個鈕把預設日曆與每本導師日曆在今天前後一年內的**所有**事件刪掉（`listWindow` 不帶標籤過濾；已取消的略過），本地則與全部清場共用 `wipeAllLocalData()` 整個清空（先拍快照，之後同樣問要不要一併清快照）；不必開「授權寫入」——唯讀設定下這一次臨時申請寫入 scope（`ensureGcalToken(GCAL_WRITE_SCOPE)`），做完即丟棄 token、開關不動（免得為了 debug 開了寫入忘記關回唯讀）；要在 prompt 輸入 `DELETE`。
- Token 只存記憶體，刷新頁面即失效；未授權／離線時明確報錯，本地功能不受影響。ICS 導出保留作無網降級。
- 日曆入口收斂為兩個：「同步 GCal」（推送＋拉回＋清殘留一體）與「導出 .ics」無網降級（原「導入 GCal (API)」「同步對帳」「清理 GCal (API)」三按鈕已合併；「逐堂 GCal 建立頁」與每行「+ Calendar」預填連結曾一度移除，v3 以「加進 GCal」的形式只在唯讀模式、只對補堂／加課重新提供——見上方寫入授權開關一節）。

# Demo Music Studio 脫敏測試版

這是用於開發、測試和演示的通用脫敏版本，不代表任何真實機構或客戶。

## 運行

- **Windows：雙擊 `serve.cmd`**（推薦）：用倉庫附帶的便攜 Node 起本地伺服器並自動開瀏覽器 `http://127.0.0.1:5500/`。
- **macOS：雙擊 `serve.command`**：有 Node 用 `serve.js`，否則用系統 `python3`（首次可能提示安裝命令列工具）；被 Gatekeeper 擋下時右鍵 → 打開。
- **多人／多裝置使用：把整個資料夾放上靜態網站託管**（GitHub Pages、Cloudflare Pages 等，免費含 HTTPS），把該網址加入 GCP 的 Authorized JavaScript origins，之後任何電腦或手機開網址即可，不需本地伺服器。資料仍是各裝置瀏覽器各自一份，換裝置用「全量備份／還原」搬。
- 或 VS Code 開啟本資料夾 → 右下角「Go Live」（Live Server 擴充，同為 5500 埠）。
- 直接雙擊 `index.html`（`file://`）也能用本地功能，但 **Google OAuth 不支援 file://**，GCal 三個 API 按鈕會用不了；且 `file://` 與 `http://127.0.0.1:5500` 是不同 origin、`localStorage` 資料各自獨立——請固定用同一種方式開啟。

所有資料均為虛構測試資料，只保存於瀏覽器 `localStorage`，不會改動其他版本。

## 脫敏聲明

- 不包含真實學生、導師、電話、電郵、機構名稱或客戶識別資料。
- 測試電郵只使用 `example.com`，電話使用零佔位號碼。
- 不包含地區或真實貨幣標識；金額僅作為無貨幣單位的演示數值。
- 請勿在此目錄放入真實客戶資料，也不要把此版本當作生產資料庫。

## 功能（v2）

- 脫敏學生測試資料（14 人，每導師 5–8 名）和學生 CRUD。情境覆蓋：2 人小組（S003/S004，同時段豁免與 TL 聯動）；樂理 Grade 5 五人小組班 `G01`（Instructor B 週六 15:00）——Student 020/021 同時有自己的一對一課，Student 030–032 只上小組課（`weekday: null`＝沒有個別課）
- **資料模型：學生＝人，報讀項目分兩類。** 個別課掛在學生記錄上（最多一個：星期／時間／時長／課程／級別）；**小組班是獨立實體**（`gac_groups_v2`：名稱／課程／級別／導師／星期／時間／時長／`memberIds`），學生經成員名單加入、可同時屬多個小組。總課表「新增小組」建立、chip 上 ✏️ 編輯成員與時段（含撞堂預覽）；學生弹窗也可勾「所屬小組」；學生名單庫每人一行、「常規上課時間」欄列出全部報讀項目（個別＋各小組）。生成時勾學生＝他的個別課、勾小組＝整組（merge 範圍按 groupId 圈定，只勾個別課不會誤刪小組課）；每位成員各自一筆課堂（出席／請假／學費按人），共享 `groupId` 讓課表／日曆／薪酬把同時段當「一節」。學費按人合計、每堂按自身費率查價；薪酬每個報讀項目一行（`學生 @ 小組名`）
- 總課表持久化（`gac_lessons_v2` 按月分桶）；重新生成為 merge 語義，已有狀態不會被清空
- 常規時間／升班調整已併入總課表（原「單一學生」頁籤移除）：學生列表每行 ✏️ 開快速編輯——星期／時間／時長／級別（升班）、「生效月份」保留歷史時間；儲存前**即時預覽**該月與同導師其他課的撞堂（已生成月份按實際課表、未生成月份按各學生常規時間模擬）。保存後到對應月份按「生成」套用；原班際課程的一次性排堂預覽一併移除（資料保留在 `data.js`）
- 課堂狀態機：已排課／已上課／請假（事假 L、病假 SL、導師請假 TL）／NoShow；非法轉換被攔截，批量確認出席
- 請假與補堂兩步解耦：先標記請假，隨時從「待補堂池」（跨月、按等待天數排序）安排補堂；防重複排堂
- 補堂可倒回：還原「已排補堂的請假」會級聯確認並一併取消補堂；請假行內可直接「改期補堂／取消補堂」
- 小組課防護：TL 導師請假全組聯動；補堂時段發散攔截與總表頂部不一致警告橫幅；同一導師時間重疊（撞堂）檢測，小組同時段豁免
- 手動模式：跳過狀態機限制直接改狀態、不觸發小組聯動（每次載入預設關閉，用於修正誤操作）
- 彈窗原則：成功提示一律右下角 toast（3.5 秒淡出，不阻斷）；`confirm` 只留給不可逆或牽連他人的操作（刪除學生／小組／條目、清場與還原、請假與排補堂、取消補堂、級聯取消補堂、整組 TL 請假、批量確認出席、清除排定變更）；`alert` 只用於必填欄位缺漏、系統錯誤與需人工處理的衝突報告。「還原為已排課」「全組出席」「手動模式改狀態」「建立群發」均為可逆，不再彈確認
- 發送中心：學費、請假確認、補堂確認訊息雙欄管理（待發送／已發送，按月獨立；「類別」下拉只列本月實際存在的類別，自定義群發按訊息名稱列二級子分類——選中即只顯示該批，兩欄計數隨之變動，頁籤紅點徽章仍計全部）；「標記已發」（wa_link）／「手動已發」（manual）／「移回待發」；無電話學生僅可複製或手動已發；學費金額可行內手改（重新生成不覆蓋）。點開 WhatsApp 的處理可設定：預設安全模式（標記「已開啟」＋切回頁面時詢問是否已發），可降級為只標記或點開即自動移欄——瀏覽器無法得知訊息在 WhatsApp 裡是否真的送出
- **自定義群發**（發送中心）：先起訊息名稱（如「調整學費」——會成為「類別」下拉「自定義」組的二級子分類，建立後自動聚焦該批），再寫訊息內容（`{name}`／`{id}` 佔位符按學生解析定稿），按導師篩選、勾選學生後批量加入「待發送」欄；同月可多次群發互不覆蓋，建錯的條目可在卡片上直接刪除，其後的複製／WhatsApp／標記已發流程與其他訊息一致
- 設定頁：NOSHOW 是否計薪、WhatsApp 發送確認方式、公開 ICS 網址、Google Calendar OAuth 參數（Phase 2 使用）
- 薪酬按實際上課（ATTENDED）統計，補堂按實際上課日期歸屬月份；NOSHOW 計薪依設定。高級薪酬表**按導師分組**，每導師一行小計（學生行數／人次堂數／**導師節數——小組同時段只算 1 節**、按課表計／課程總額／導師應得）；「隱藏 0 堂學生」預設開啟（0 堂行仍在資料中，取消勾選即顯示）；頂部堂數 KPI 同時顯示人次與節數
- 清單（操作）＋月曆（總覽）兩種視圖（原週曆與逐堂 Google Calendar 預填連結已裁剪——清單按週次過濾＋API 導入完全覆蓋其用途）；整月 ICS 導出（VEVENT 含 `UID:<lessonId>@guitaristic`）
- Google Calendar API 同步（Phase 2，見下節）：查重導入絕不覆蓋、對帳 diff 逐條勾選套用
- WhatsApp Web 預填訊息連結（只使用演示電話號碼）
- 全量 JSON 備份／還原（學生＋課表＋發送紀錄＋設定，帶 schema 版本檢查；舊版「僅學生名單」備份檔兼容匯入）

## Google Calendar 同步（Phase 2）

一次性設置：

1. [GCP Console](https://console.cloud.google.com/) 建專案 → 啟用 **Google Calendar API** → Credentials 建立 **OAuth client ID**（類型 Web application）。
2. Authorized JavaScript origins 加入你開啟本頁的網址。**GIS 不支援 `file://`**，請用本地伺服器（如 VS Code Live Server 的 `http://127.0.0.1:5500`）。
3. 把 Client ID（及目標日曆 ID，預設 `primary`）填入本系統「設定」頁。

使用（總課表頁頂部）：

- **同步 GCal**（單一入口）：一次授權、一次抓取本月前後各 7 天的事件，兩邊差異分組列在同一面板，勾選後執行——**預設勾選＝執行後兩邊一致，GCal 上的改動以 Calendar 為準**：
  - ⬆️ **推送**：本地有、GCal 沒有 → **一節一個事件**：一對一按 `private.gacLessonId` 查重，標題 `S001 Student 001([1/5] 09/2026)`；小組課同時段全組**只建一個事件**，按 `private.gacCellKey` 查重，標題 `Music Theory Grade 5 小組 ×5 (09/2026)`、description 列成員、`private.gacLessonIds` 存成員清單，事件 id 回填到全體成員。**絕不 update 既有事件**；location 放狀態碼（L/SL/TL/MU/NS，小組全員同碼才寫）。
  - 🕒 **時間變更**／🏷️ **狀態碼變更**：GCal 上被挪動或標了 L/SL/TL/NS → 更新本地（lessonId 不變，跨月自動移桶；小組事件對全體成員生效）。
  - 🗑️ **已刪除**：成員曾回填的事件已不在 GCal → 本地標記請假（一對一事假 L；小組事件被刪＝整堂取消 → 全組導師假 TL）；一次 ≥5 節視為批量清場而非逐堂取消，該組改預設不勾並警告（避免整批誤標請假灌爆待補堂池）。
  - 🧹 **殘留**：標籤對不上任何本地課節（本地改動／重新生成後的舊事件，以及小組課改為一節一事件前推送的逐人舊事件）→ 從 GCal 刪除（垃圾桶可還原；**手動建立的事件永遠不會出現在任何組**）。
  - ➕ **手動新建**：GCal 手動建立、標題可歸屬學生的事件 → 逐條選擇收編為補堂或獨立加課（預設不勾）。
  不做無人值守的自動同步（token 只存記憶體，每次刷新都需重新授權，執行前可全覽差異）。
- **清空本月／全部清場**（設定頁危險區）：測試點亂後重來。**清空本月**只清總課表目前檢視的月份——該月 GCal 帶標籤事件（含被刪課堂掛連的跨月補堂事件）、本地整月課堂（級聯刪跨月補堂鏈；其他月份請假若其補堂被刪則解鏈回待補池）、該月發送紀錄（含已發送）。**全部清場**刪今天前後一年內所有帶標籤 GCal 事件並清空本地全部月份（課堂／發送紀錄／薪酬調整與封存）。兩者都絕不刪 GCal 手動事件（刪掉的可在垃圾桶還原）；本地不可還原，先全量備份。學生名單與設定保留；未設定 GCal 時只清本地。
- Token 只存記憶體，刷新頁面即失效；未授權／離線時明確報錯，本地功能不受影響。ICS 導出保留作無網降級。
- 日曆入口收斂為兩個：「同步 GCal」（推送＋拉回＋清殘留一體）與「導出 .ics」無網降級（原「導入 GCal (API)」「同步對帳」「清理 GCal (API)」三按鈕已合併；「逐堂 GCal 建立頁」與每行「+ Calendar」預填連結亦已移除）。

## 文件

- `index.html`：頁面與五個功能頁籤（總課表／學生名單庫／高級薪酬／發送中心／設定）
- `data.js`、`art-rate-data.js`：課程選項、測試資料、費率與日曆狀態碼
- `state.js`：頁面內存狀態
- `app.js`：排堂、狀態機 UI、待補堂池、小組防護、發送中心、備份還原
- `payroll-advanced.js`：高級薪酬計算
- `gcal-ui.js`：Google Calendar 同步的瀏覽器膠水層（GIS OAuth、導入、對帳彈窗）
- `lib/`：無 DOM 依賴的純函數庫（`schedule.js` 生成與 merge、`lessonState.js` 狀態機與補堂鏈、`payroll.js` 計薪、`sendlog.js` 發送紀錄、`storage.js` 持久化與備份、`gcal.js` 日曆事件構造／查重導入／對帳 diff）
- `tests/`：Node 內建 test runner 的單元測試
- `styles.css`：頁面樣式

## 測試

無需安裝 Node：倉庫附帶便攜版（`.tools\node\`，已被 gitignore）。

```
run-tests.cmd
```

或手動執行：

```
.tools\node\node.exe --test "tests/*.test.js"
```

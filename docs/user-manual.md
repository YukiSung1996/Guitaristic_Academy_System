# 使用手冊（精簡版）

給學校職員與導師。頁面請用 http 開（`serve.cmd` 或 VS Code Live Server），不要用 file://。

用 `serve.cmd` 開：資料存在**本資料夾**的 `local-state.json`，每個資料夾各自一份（演示、真實各開各的，互不干擾）。用 Live Server 開：資料存在瀏覽器，同一網址的資料夾共用。第一次用 serve.cmd 開時若瀏覽器留有舊資料，會問要不要搬進本資料夾。

按重新整理（F5）會回到原處：同一個頁籤、各頁選的月份、總課表的清單／月曆、捲到的位置（連清單裡面捲到哪）都不變；篩選和搜尋會清空。關掉再開（或用 serve.cmd 開一個新分頁）則從「全校時間表」、本月開始。

## 一、開始前（只做一次）

| 步驟 | 在哪 | 做什麼 |
|---|---|---|
| 1 | 設定 → 導師 | 新增導師；每位貼上自己的 Google 日曆 ID，按「測試」確認讀得到 |
| 2 | 學生名單庫 | 新增學生／小組：導師、星期、時間、時長、費率。只上小組的學生取消勾選「有常規私教課」，只勾所屬小組 |
| 3 | 設定 → Google Calendar | 填 OAuth Client ID、預設日曆 ID。「授權寫入」關＝**唯讀模式**（預設），開＝**讀寫模式**。選「兩邊都改了時以哪邊為準」 |
| 4 | 頂部 | 「全量備份 (JSON)」隨時可備份；「撤銷」退回上一步 |

## 二、每月流程（兩種模式相同）

| 順序 | 按鈕 | 功能 |
|---|---|---|
| 1 | 全校時間表 → 選月份 → 生成 | 按學生固定時段排出整月常規課 |
| 2 | 📋 清單／📅 月曆 | 檢查課表；同導師同時段撞課會標黃。選導師 → 學生下拉只列他的學生；選學生 → 導師自動跟隨，月曆與週次下拉只列該生有課的星期 |
| 3 | 放進 Google Calendar | 讀寫：同步 GCal 推送。唯讀：導出 .ics 再匯入。細節見三、四 |
| 4 | 平時處理請假／缺席／改期／補堂 | 在系統或 Calendar 做都可以。細節見三、四 |
| 5 | 同步 GCal | 比對兩邊差異，勾選後執行，兩邊一致 |
| 6 | 發送中心 | WhatsApp 發請假確認／補堂確認／改期通知 |
| 7 | 批量確認出席 | 已過時間、仍是已排課的課標出席。不會推到 Calendar |

## 三、讀寫模式（授權寫入＝開）

系統可以直接改 Calendar。每節課一個事件，推到該導師的日曆。

| 我想 | 在系統做 | Calendar 那邊 |
|---|---|---|
| 整月放進 Calendar | 同步 GCal → 勾「⬆️ 推送」→ 執行勾選項目 | 自動建立 |
| 請假／缺席 | 課卡「請假」或「NS」→ 按「寫回 GCal 狀態」 | 事件自動寫上 狀態：L／NS |
| 改期、排補堂 | 改期或排補堂後，彈窗頂部「同步到 Google Calendar 嗎？」按一下 | 改原事件或建新事件，不會重複 |
| 取消補堂 | 課卡「取消補堂」 | 事件留著，下次同步在「🧹 殘留」勾掉 |
| 在 Calendar 直接建補堂 | 待補堂池「複製標題」「複製內容」→ 貼到新事件；同步 GCal → 「➕ 手動新建」選「作為補堂 ←」 | 系統連上這個事件，不另建 |
| 在 Calendar 改了（拖時間、填狀態、手動建課） | 同步 GCal → 勾選拉回 | — |

待補堂池（已請假、還沒排補堂的課）在總課表頁月曆／清單的下面，預設展開；點標題可收起。頁面頂部的「辦理補堂/請假」卡可以點，直接跳到待補堂池（沒有待補的就列出本月的請假與補堂）。

撞堂：頂部「時間衝突/撞堂警報」卡的數字是組數（一對重疊的課算 1）。有撞堂時，清單一律把撞堂的課排在最前面，按「誰和誰重疊」分組；每組把其中一節按「改期」移走即可。清單視圖下，課表上方的撞堂提示條右邊有切換：「只顯示撞堂／顯示全部」。月曆一律顯示全部（撞堂的課有紅框），提示條上按「到清單處理」。點頂部那張卡會直接切到清單並只顯示撞堂。課表篩選列的「所有課堂／請假與補堂／⚠️ 撞堂」下拉是同一個功能。

小組課改期是整節的事：按小組卡頭的「全組改期」，仍是已排課的成員一起搬到新時段（已請假的不動），每位成員各有一筆改期通知，Calendar 上仍是同一個事件。整組一起補的補堂也一樣，在卡頭按「全組改期」或請假那張卡的「全組改期補堂」。成員那一行不再有改期鈕；真的要只動一位（修資料），開「手動模式」。改期時的撞堂提示只列新時段真的撞到的課，請假的課不佔時段。

畫面右下角有一顆懸浮的「GCal」圓形按鈕，和總課表頂部的「同步 GCal」是同一個功能，任何頁籤、滑到哪裡都按得到；按住可以拖到別的位置（位置記在這個瀏覽器）。批量推送／刪除會同時送幾件（預設 6，設定 → Google Calendar「批量推送／刪除時同時送幾件」可改，1–10），整月四五十節幾秒內完成；送太密被 Google 暫時擋下時會自動等一下再試。

同步面板各組：⬆️ 推送、🔁 本地改期、📦 搬到導師的日曆、📤 寫回狀態、✏️ 更正標題、🕒 時間變更、🏷️ 狀態碼變更、🗑️ 已刪除、🧹 殘留、➕ 手動新建。預設勾選＝執行後兩邊一致。每組可按標題收起（收起不影響勾選，標題右邊顯示「已勾 x／n」），標題右邊有該組的「全選／全不選」；面板頂部固定著一排按鈕（清單再長也不用滑到底）：「全選／全不選」管全部，「全部收起／展開」一次收放所有組，右邊是「取消」「執行勾選項目」。兩邊都改了時，按設定「以哪邊為準」。⚠️ 狀態衝突（系統已出席、Calendar 填了請假／缺席）預設不勾，先查清楚。

**只比最後結果**：同步比的是「現在的系統」和「現在的 Calendar」，不是把你按過的每一步重做一次。

- 改了又撤銷、或改回原樣，兩邊一樣就什麼都不列。
- 已經同步到 Calendar 之後才撤銷的（例如改期、請假已寫上去）：系統記得 Calendar 上那個樣子是它自己寫的，所以會列成「🔁 本地改期」或「📤 寫回狀態」把 Calendar 改回去，不會把撤銷掉的改動又從 Calendar 拉回系統。
- 導師在 Calendar 上改的，照舊列在「🕒 時間變更」「🏷️ 狀態碼變更」拉回系統；兩邊都改了才看「以哪邊為準」。
- 系統是在每次同步時記下「兩邊一致的樣子」：更新到這一版之後，要先同步過一次，之前已同步的課才有這個記錄。

**排序**：面板每一組裡，最近改動的排在最前（系統這邊看那節課最後一次改動的時間，Calendar 那邊看事件最後修改的時間）；同一次生成的整個月再按上課日期排。撤銷也算一次改動。

## 四、唯讀模式（授權寫入＝關）

系統只讀 Calendar，不會改。Calendar 那邊要人手做；系統按事件標題（學號／姓名／小組名）認課。

| 我想 | 在系統做 | 然後在 Calendar 人手做 |
|---|---|---|
| 整月放進 Calendar | 導出 .ics（每位導師一個檔） | Google 日曆 → 設定 → 匯入，選該導師的日曆 |
| 請假／缺席 | 課卡「請假」或「NS」→「在 GCal 填 狀態：L」 | 打開的事件說明欄填 L／SL／TL／NS，儲存 |
| 改期 | 改期 → 「改 GCal 舊事件（舊 → 新）」 | 打開的事件把時間改成新的，不要另建 |
| 排補堂 | 排補堂 → 「加進 GCal」 | 已填好的新建頁，「日曆」欄選該導師的日曆，儲存 |
| 取消補堂 | 取消補堂 | 打開的事件按刪除 |
| 在 Calendar 直接建補堂 | 待補堂池「複製標題」「複製內容」；之後同步 → 「➕ 手動新建」選「作為補堂 ←」 | 在該導師的日曆新建事件，貼上標題與說明，填時間 |
| 直接在 Calendar 改 | — | 拖時間；說明欄「狀態：」填碼；補堂可直接建事件 |
| 拉回本地 | 同步 GCal（唯讀）或 匯入 ICS → 勾選執行 | — |

面板裡「📌 請到 Calendar 改」「📝 請到 Calendar 填」＝還沒人手做的項目，做好再同步就消失。

Calendar 標題寫法不用很準：系統認人只看標題開頭的學號（少寫前面的零也行）或姓名，加上日期；標題裡的「第幾節／共幾節」寫錯不影響配對。標題和課表對不上時（編號錯、手打的標題），寫入模式在「✏️ 更正標題」勾選即直接改 Calendar 上的標題；唯讀模式列在「✏️ 標題提醒」，逐個按「複製正確標題」到 Calendar 貼上（只是提醒，不改也不影響同步）。Calendar 上本月的事件比課表多或少，會分別列在「➕ 手動新建」與「⬆️ 推送／🗑️ Calendar 上沒有這堂」。

## 四之二、下載糧單（高級薪酬管理頁）

月底把出席都確認好（總課表「批量確認出席」）、津貼／扣款填好之後：

| 我想 | 按哪裡 | 得到什麼 |
|---|---|---|
| 全部導師一次下載 | 頁頂「下載糧單」的 Excel 或 PDF | 一個檔：Excel 每位導師一個工作表；PDF 每位導師另起一頁 |
| 只要一位導師 | 該導師那一行右邊的綠色（Excel）或紅色（PDF）小圖示 | 只有他一位的檔，檔名帶導師名 |

- 糧單內容：標誌、月份標題、導師名、下載當天的日期、Cheque #（留空，印出來手寫或在 Excel 裡填）、每位學生一列（級別、每堂價、堂數、金額、導師應得、備註）、Sub Total、「樂器銷售佣金／其他調整」、Total。
- 只算已確認出席的課（已上課＋缺席）。還有課沒確認時，下載後右下角會提示有幾堂沒計入。Total 與頁面上該導師的「目前應付」相同。
- 「樂器銷售佣金／其他調整」放的是「額外津貼／扣款」裡指名給這位導師的項目（扣款是負數）；選「全月（不分導師）」的不會出現在任何一張糧單上。佣金要出現在糧單上，就在「額外津貼／扣款」新增一筆並指名導師。
- 備註會自動寫：小組名、含補堂幾堂、含缺席幾堂。同一位學生月內有不同價錢的課（例如時長不同）會分成兩列。
- Excel 檔的金額是公式，下載後可以直接改堂數或加一列，合計會跟著變；PDF 不能改。
- 換標誌：用真實標誌的圖檔（PNG 或 JPG）覆蓋資料夾裡的 `assets/paysheet-logo.png`，檔名不變。建議寬:高＝6:1（例如 1200×200）；比例不同也可以，會等比例縮放、置中。

## 五、狀態碼（Calendar 說明欄「狀態：」那一行）

| 碼 | 意思 |
|---|---|
| 留空 | 沒填。系統不動它；出席在系統「批量確認出席」即可，不用寫回 |
| A | 出席 |
| L／SL／TL | 事假／病假／導師請假 |
| NS | 缺席 |
| MU | 補堂標記，不是狀態 |

中文也認：出席、請假、病假、導師請假、缺席。

## 六、重來

設定 → 危險區：「清空本月」「全部清場」清 Calendar 帶標籤事件＋本地（唯讀模式只清本地）；「強制清空」刪日曆所有事件，debug 用。按之前先「全量備份」。

## 七、換成真實名單

1. 用真實的 `data.js` 覆蓋演示版（不要提交進 git：`git update-index --skip-worktree data.js`）。
2. 設定 → 危險區「從 data.js 重新載入名單」：學生、小組班、導師都重讀。頁面平時只讀 localStorage，不按這個不會生效。
3. 「全部清場」清掉演示課表，再「生成」。
4. 設定頁填機構資料：FPS、網址、學費單尾段、Google Client ID、各導師日曆 ID。
5. 想回到演示情境：設定 → 危險區「還原演示名單」（讀 `demo_data.js`），再「全部清場」→「生成」。之後「從 data.js 重新載入名單」即換回真實名單；導師日曆 ID 兩邊都記住，不用重填。


## 八、學生狀態（在學／停課）與學號寫法

**學生狀態**：學生名單 → 編輯 → 最下面「學生狀態」選「在學」或「停課」。

- 選「停課」後填「由哪天起停課」（預設今天）。可以預定：例如填下個月 1 號，到那天才算停課，之前照常上課。
- 復課日＝當天起恢復上課；留空＝未定，之後生成的每個月都略過這位學生。
- 改回「在學」＝今天起復課；還沒開始的預定停課則直接取消。要預定某天復課，保持「停課」並填復課日。
- 停課的日子生成時不出課：不收學費、不佔時段、不推 Calendar。精確到日，月中停課或月中復課只略過那幾天。
- 小組成員停課：只略過他那幾天，其他成員照常，小組收費不變。
- 名單：今天正在停課的學生收在名單下方「停課學生」（預設收起，標題有人數），那一行有「復課」鈕；預定停課但還沒到日子的仍在上面，標「將停課」。頁面頂部顯示在學人數，另寫有幾位停課。
- 已經生成好的月份：儲存狀態時會問一次要不要一併處理——停課期間仍是「已排課」的課移除、復課後空出來的日子補生成、學費條目跟著更新；只動這位學生的課。已上課／請假／缺席的課與補堂不會動，會列出來請你人工處理。按「取消」只存狀態，之後到該月按「生成」也會套用。已推到 Calendar 的課，下次「同步 GCal」會列出要刪的事件（唯讀模式要自己到 Calendar 刪）。
- 小組只剩一人：把某位學生設成停課後，如果他所屬的小組（小組班，或兩人同時段的「2人小組」）因此只剩一位在學的學生，會彈出提示，逐個小組選：保留照常上課（收費照原本的小組價）、剩下那位也停課（同樣的日期）、或去編輯那位學生／小組（例如改成個別課、解散小組）。系統不會自動替你改。之後想再處理：學生名單下方的小組班列表會標「⚠️ 只剩 1 位在學」，停課的成員標「（停課）」。
- 自定義群發：停課中的學生預設不勾。

**學號寫法**：前面補不補零都算同一號，英文字母不分大小寫。例如 32、032、0032 是同一位學生。

- Calendar 事件標題用「32 陳大文」或「032陳大文」開頭，同步時也認得是 0032。
- 以時間或日期開頭的標題（如「15:00 …」「10/07 …」）不會被當成學號。
- 新增學生時，學號與現有學生同號會被擋下。
- 搜尋框輸入 32 或 0032 都找得到。

## 九、訊息模板（設定 → 訊息模板）

學費單、請假確認、補堂確認、改期通知、催繳、收款確認的文字都可以改。**照打的樣子發出**：空一行就有空行，不空就沒有，系統不會自己加空行。

學費單是一整段。明細、總額、FPS、附註、守則連結都是佔位符，放在哪一行由你決定：

| 佔位符 | 會變成 |
|---|---|
| {month}／{m} | 2026年10月／10 |
| {name}／{id} | 學生姓名／學號 |
| {details} | 上堂明細：每個報讀項目一段（日期、時間、級別、上課形式、導師、每堂學費、堂數、合共）；多於一項時，各段之間空一行 |
| {amount} | 總額（一定有） |
| {total} | 總額，只有多於一個報讀項目時才有 |
| {fps}／{notice}／{rules} | FPS 轉數快 ID／學費單附註／學員守則連結（在「學費單與繳費」填） |

- {total}、{fps}、{notice}、{rules} 沒有內容時，**所在的那一整行不出現**。例如「總額：{total}」在只有一個報讀項目時整行消失；沒填 FPS 就沒有 FPS 那一行。
- 框下面有預覽，邊打邊看；可切換「一個報讀項目／多個報讀項目」。預覽用一張真的學費單（本月的優先），沒有就用示例。
- 預設的樣子（一個空行都沒有）：

```
【學費】
你好，以下是 {month} 的學費單：
【{m}月份上堂詳情及學費】
學生：{name}
{details}
總額：{total}
＊以上收費均以每位學生計算
{fps}
{notice}
{rules}
```

- 想在哪裡空一行，就在那裡多按一次 Enter，留一行空白。

- 框留空或按「還原預設」＝用預設文字。改了模板，已建立但還沒發送的訊息也會跟著變；已發送的紀錄不變。
- 舊版的學費單分「開頭／總額／結尾」三格，更新後自動合成一整段：改過的字照舊，以前系統自己在各段之間加的空行不再加；沒改過的格用新的預設。只把開頭改成不空行的（像上面那樣），更新後就是預設的樣子，不用再改。

## 十、小組班（2 人、5 人都一樣）

小組一律用**小組班**：學生自己的常規課只有一對一（學生表單的「授課形式」只有一對一）。2 人小組和 5 人小組完全一樣：一節課一個 Calendar 事件，可以全組請假、全組改期，撞堂和導師節數都按一節算。收費按小組人數查收費表（2 人＝2人小組價，3 人以上＝3-4人小組價）。

- 建小組班：學生名單庫「+ 新增小組」，填課程、級別、導師、星期時間，勾成員。只上小組的學生，在學生表單取消勾選「有常規私教課」。
- 舊資料（以前把「2人小組」寫在學生自己的常規課上）：打開程式時會彈出「小組形式改用小組班」。系統把同一位導師、同一時間、課程級別時長都一樣的學生配成一組，列出來給你確認。
  - 按「轉成小組班」：建小組班，這幾位改成只上小組，**下個月起**按小組班排課；**本月已生成的課不動**。下個月以後已經生成的月份，這幾位的課一併改成小組課，出席、請假記錄保留。每堂收費不變。按頂部「撤銷」可以退回。
  - 配不上的列在「要你處理」（例如只有一位學生、同一時段課程不一樣、轉了收費會變）：照舊排課、收費。他的學生表單會鎖住，只改電話等資料不會動到他的課；要改按「改成一對一」，或自己建小組班把他加進去。
  - 按「稍後再說」也沒關係：學生名單上方會一直提示，按「轉成小組班…」再打開。

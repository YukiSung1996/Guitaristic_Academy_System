# Google Calendar 操作指南（唯讀模式）

給在 Google Calendar 上改課表的導師／行政看的。適用於系統設定「授權寫入 Google Calendar」**保持關閉**（預設）：系統只讀不寫，Calendar 上的改動由你動手，系統同步時把差異列出來，你逐條勾選才套用。

## 0. 先記住三件事

1. 系統只看事件的三樣東西：**標題**（誰的課）、**開始時間**（哪天幾點）、**狀態碼**（地點欄，或標題末尾；表示請假／缺席）。其他欄位——說明、顏色、提醒、邀請對象、附件——系統一律不看，隨便改。
2. **出席不能在 Calendar 標。** Calendar 沒有「上了課」這個概念。出席在系統的總課表按「批量確認出席」。
3. **沒有任何改動會自動進系統。** 同步面板把差異列出來，你勾了、按執行，才會改本地記錄。看錯了不勾就是。

## 1. 系統寫出來的事件長什麼樣

匯入 .ics 或按「加進 GCal」建立的事件：

| 欄位 | 內容 | 例子 |
|---|---|---|
| 標題 | `學號 姓名([本月第幾節/本月共幾節] 月份)` | `S001 Student 001([2/5] 09/2026)` |
| 標題（小組課） | `小組名 小組 ×人數 (月份)` | `Music Theory Grade 5 小組 ×5 (09/2026)` |
| 時間 | 上課日期、開始與結束時間 | 2026-09-16 15:00–15:45 |
| 地點 | 狀態碼；空白＝一般已排課 | 空白、`MU`（補堂）、`L`／`SL`／`TL`（已請假）、`NS`（缺席） |
| 說明 | 給人看的備註 | `Guitaristic Academy Lesson`<br>`導師：Instructor B` |

補堂事件的說明多一行 `↩ 補 2026-09-16 15:00 的請假課`。

**說明欄那兩三行純粹是備註，系統不讀。** 「導師：Instructor B」不是系統判斷導師的依據——事件放在**哪位導師的日曆裡**才是（設定 → Google Calendar → 導師日曆 ID）。說明欄改了、刪了、加了東西，都沒有影響。

補堂與加課的標題會是 `([0/5] …)`，第幾節寫 0 是正常的（補堂不編號）。

## 2. 系統怎麼認出「這是誰的課」

按這個次序試：

1. 標題**以學號開頭**，學號後面是空格或就此結束 → 那位學生。`S001 Student 001([2/5] 09/2026)`、`S001 補堂` 都可以。
2. 否則標題**含學生姓名**（至少兩個字；多人命中取最長的名字）。
3. 否則標題**含小組名稱** → 那個小組。
4. 都不是 → 略過。面板會顯示「另有 N 個事件無法歸屬學生／小組」。

所以：

- **不要改掉標題開頭的學號。** 後面加字沒關係（例如加狀態碼）。
- 學生名字別打錯。
- 把標題改成另一個學生＝系統認為原來那堂不見了、另一位學生多了一堂。

## 3. 狀態碼

| 碼 | 意思 |
|---|---|
| `L` | 事假 Leave |
| `SL` | 病假 Sick Leave |
| `TL` | 導師請假 Tutor Leave |
| `NS` | 缺席 No Show |
| `MU` | 補堂標記——不是狀態，只是讓人一看知道這堂是補堂；新建補堂事件時可加可不加 |

寫在哪：

- **地點欄**：只寫這個碼，不要有別的字。`L` 對；`L 課室2` 不對。
- **標題末尾**：一個空格，然後碼。`S001 Student 001([2/5] 09/2026) L`。

規則：大寫；要是**獨立的一個詞**（前後是空格或行首行尾）。`Level` 裡面的 L 不算，`NSL` 不算。同一事件兩處都有時以地點欄為準。

## 4. 我想……（操作對照）

| 我想 | 在 Calendar 做 | 同步時系統列出 | 勾選後系統做 |
|---|---|---|---|
| 學生請假 | 標題末尾加 ` L`（或 ` SL`／` TL`），或地點欄填 `L` | 狀態碼變更 → 請假 (L) | 該堂標請假、生成「請假確認」訊息、進待補堂池 |
| 學生缺席 | 標題末尾加 ` NS`，或地點欄填 `NS` | 狀態碼變更 → NS 缺席 | 該堂標缺席 |
| 同一天改時間 | 把事件拖到新的時間 | 時間變更 | 該堂改時間、生成「改期通知」 |
| 改到另一天 | 拖到另一天的話，系統會當成「原日這堂沒了」＋「新日多了一堂」（見下方說明） | Calendar 上沒有這堂 ＋ 手動新建 | 兩項都勾＝請假＋補堂。要記成「改期」的話請在系統按「改期」 |
| 排補堂 | 新建事件，標題 `S001 Student 001 MU`（MU 可不寫），設好日期時間 | 手動新建 → 下拉選「作為補堂 ←（某日 L）」 | 補堂掛到那次請假、生成「補堂確認」 |
| 加一堂（不掛任何請假） | 同上 | 手動新建 → 「獨立加課」 | 多一堂 |
| 整堂取消、不補 | 刪掉事件 | Calendar 上沒有這堂 | 標請假（一對一記事假 L；小組記導師假 TL） |
| 取消已排的補堂 | **在系統按「取消補堂」。** 在 Calendar 刪補堂事件，系統只會提議把補堂標請假，不是取消 | — | — |
| 確認出席 | **做不到。** | — | 系統「批量確認出席」 |
| 把系統排的補堂放進 Calendar | 系統補堂課卡按「加進 GCal」→ 選日曆 → 儲存 | 下次同步認得是同一堂，不會再列出 | — |

關於「改到另一天」：唯讀模式下系統是按「同一位學生、同一天」配對的，所以事件跨日拖走，系統在原日找不到、在新日多見一個。兩項都勾的結果是那天照樣上課、薪酬照算，只是記錄上是「請假＋補堂」而不是「改期」，訊息也會是請假確認＋補堂確認。想要乾淨的「改期」記錄，在系統課卡按「改期」，再按「加進 GCal」或自己在 Calendar 拖。

關於「Calendar 上沒有這堂」：系統只在三個條件都成立時才敢這樣判斷——只看本月；只針對系統裡仍是「已排課」的堂（已請假、已上課的不管）；而且系統知道這本日曆屬於哪位導師（設定裡填了該導師的日曆 ID，或匯入 ICS 時選了導師）。不確定是誰的日曆時面板會說明並跳過這項，以免把別的導師的課整批誤判成取消。

## 5. 其他要注意的

- **全日事件**沒有時間，不能收編。補上開始時間。
- **每週重複事件**沒問題，同步時會逐次展開比對。
- **一位導師一本日曆**：事件在誰的日曆裡就算誰的課。放錯日曆＝系統在 A 的日曆找不到 A 的課（會提議請假），又在 B 的日曆多出一堂認不出的課。
- **匯入同一個 .ics 兩次不會重複**：事件 UID 固定，Google 依 UID 查重。
- **沒有 Google 授權也行**：Google Calendar 網頁 → 設定 → 匯入及匯出 → 匯出（會得到 zip，解壓後每本日曆一個 .ics）→ 系統總課表「匯入 ICS」→ 選這是哪位導師的日曆 → 上傳。規則和上面完全一樣，只是不用登入。

## 6. 每月的節奏

1. **月初**：系統「生成」當月課表 → 「導出 .ics」（自動一位導師一個檔）→ 每位導師把自己的檔匯入自己的 Google 日曆（Google Calendar 設定 → 匯入及匯出 → 匯入）。
2. **平時**：出席在系統批量確認；請假、補堂、同日改時間可以在 Calendar 按第 4 節做。
3. **每週同步一次**：總課表「同步 GCal」（或「匯入 ICS」），逐條勾選要套用的差異。
4. **同步之後**：系統生成的請假確認／補堂確認／改期通知在「發送中心」發給家長。

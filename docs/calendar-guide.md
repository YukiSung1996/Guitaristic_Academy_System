# Google Calendar 操作指南（唯讀模式）

給在 Google Calendar 上改課表的導師／行政看的。適用於系統設定「授權寫入 Google Calendar」**保持關閉**（預設）：系統只讀不寫，Calendar 上的改動由你動手，系統同步時把差異列出來，你逐條勾選才套用。

## 0. 先記住三件事

1. 系統只看事件的三樣東西：**標題**（誰的課）、**開始時間**（哪天幾點）、**狀態碼**（說明欄「狀態：」那一行；表示出席／請假／缺席，留空＝沒填、系統不動）。說明欄其他行、顏色、提醒、邀請對象、附件——系統一律不看，隨便改。
2. **出席不能在 Calendar 標。** Calendar 沒有「上了課」這個概念。出席在系統的總課表按「批量確認出席」。
3. **沒有任何改動會自動進系統。** 同步面板把差異列出來，你勾了、按執行，才會改本地記錄。看錯了不勾就是。

## 1. 系統寫出來的事件長什麼樣

匯入 .ics 或按「加進 GCal」建立的事件：

| 欄位 | 內容 | 例子 |
|---|---|---|
| 標題 | `學號 姓名([本月第幾節/本月共幾節] 月份)` | `S001 Student 001([2/5] 09/2026)` |
| 標題（小組課） | `小組名 小組 ×人數 (月份)` | `Music Theory Grade 5 小組 ×5 (09/2026)` |
| 標題（補堂） | `學號 姓名 補堂([第幾節/共幾節] 月份 ← 原課日期)` | `S001 Student 001 補堂([2/5] 09/2026 ← 09/16)`＝補 9 月 16 日那一堂 |
| 時間 | 上課日期、開始與結束時間 | 2026-09-16 15:00–15:45 |
| 地點 | 狀態碼；空白＝一般已排課 | 空白、`MU`（補堂）、`L`／`SL`／`TL`（已請假）、`NS`（缺席） |
| 說明 | 四行：課程、導師、**狀態（你填的地方）**、填法提示 | `一對一 · Fingerstyle Guitar · Intermediate 中級`<br>`導師：Instructor B`<br>`狀態：`<br>`（出席留空或填 A；請假填 L、病假 SL、導師請假 TL、缺席 NS。系統同步時讀這一行）` |

小組課第一行是 `小組課 · 樂理 Grade 5 小組`，後面多列成員。補堂事件第一行以 `補堂 · ` 開頭，第二行寫明補的是哪一堂：`↩ 補的是：2026-09-16（三）15:00 請假的那一堂（09/2026 第 2 節）`。小組補堂的標題同樣帶 `補堂` 和 `← 原課日期`。

說明欄裡**系統只讀「狀態：」那一行**。「導師：Instructor B」是給人看的——系統判斷導師是看事件放在**哪位導師的日曆裡**（設定 → Google Calendar → 導師日曆 ID），不是這行字。第一行、導師行、提示行改了刪了都沒影響；「狀態：」後面寫了什麼才算數。

補堂標題的 `[2/5]` 是它補的那一堂的編號。獨立加課的標題會是 `([0/0] …)`，寫 0 是正常的（加課不編號）。

## 2. 系統怎麼認出「這是誰的課」

按這個次序試：

1. 標題**以學號開頭**，學號後面是空格或就此結束 → 那位學生。`S001 Student 001([2/5] 09/2026)`、`S001 補堂` 都可以。
2. 否則標題**含學生姓名**（至少兩個字；多人命中取最長的名字）。
3. 否則標題**含小組名稱** → 那個小組。
4. 都不是 → 略過。面板會顯示「另有 N 個事件無法歸屬學生／小組」。

所以：

- **不要改掉標題開頭的學號。** 後面加字沒關係（例如加狀態碼）。
- 學生名字別打錯。
- 把標題改成另一個學生＝系統認為原來那堂不見了、另一位學生多了一堂。

## 3. 狀態碼

| 碼 | 意思 |
|---|---|
| `L` | 事假 Leave |
| `SL` | 病假 Sick Leave |
| `TL` | 導師請假 Tutor Leave |
| `NS` | 缺席 No Show |
| `A` | 出席（已上課）。**留空也可以**：留空系統不當成任何狀態，出席在系統按「批量確認出席」即可，不會寫回 Calendar；只在想明確標記時才填 |
| `MU` | 補堂標記——不是狀態，只是讓人一看知道這堂是補堂；新建補堂事件時可加可不加 |

寫在哪（三個地方都認，**以說明欄為準**）：

- **說明欄「狀態：」那一行**（建議）：`狀態：L`。中文也可以：`狀態：請假`、`狀態：病假`、`狀態：導師請假`、`狀態：缺席`、`狀態：出席`。碼後面可以加註，例如 `狀態：L（家長早上通知）`。
- **地點欄**：只寫這個碼，不要有別的字。`L` 對；`L 課室2` 不對。
- **標題末尾**：一個空格，然後碼。`S001 Student 001([2/5] 09/2026) L`。

規則：碼大小寫都認；地點欄與標題的碼要是**獨立的一個詞**（前後是空格或行首行尾），`Level` 裡面的 L 不算，`NSL` 不算。三處不一致時：說明欄「狀態：」有填就以它為準；沒填才看地點欄；再沒有才看標題。

## 4. 我想……（操作對照）

| 我想 | 在 Calendar 做 | 同步時系統列出 | 勾選後系統做 |
|---|---|---|---|
| 學生請假 | 說明欄 `狀態：L`（或 `SL`／`TL`，或中文「請假」）；地點欄／標題末尾也可以 | 狀態碼變更 → 請假 (L) | 該堂標請假、生成「請假確認」訊息、進待補堂池 |
| 在系統裡標了請假／缺席，想讓 Calendar 也顯示 | 課卡（或請假確認彈窗）按「在 GCal 填 狀態：L」→ 打開該事件的編輯頁 → 說明欄「狀態：」填 `L` → 儲存。Google 不支援預填既有事件，這一個碼要自己打 | 沒填的會列在「本地標了請假／缺席，Calendar 上還沒有」附「在 Calendar 打開」連結；填好就消失 | —（只是提示，不改本地） |
| 學生缺席 | 說明欄 `狀態：NS`（或「缺席」） | 狀態碼變更 → NS 缺席 | 該堂標缺席 |
| 學生正常上了課 | 什麼都不用做（留空）；想標明也可填 `狀態：A`（或「出席」） | 留空：不列（沒有資訊）。填了 A：狀態碼變更 → 出席 | 出席在系統按「批量確認出席」；不會推到 Calendar |
| 系統已確認出席，Calendar 卻填了 L／NS | — | ⚠️ 狀態衝突（預設不勾） | 先查清楚哪邊對；勾選＝按設定「以哪邊為準」處理 |
| 同一天改時間 | 把事件拖到新的時間 | 時間變更 | 該堂改時間、生成「改期通知」 |
| 改到另一天 | 拖到另一天的話，系統會當成「原日這堂沒了」＋「新日多了一堂」（見下方說明） | Calendar 上沒有這堂 ＋ 手動新建 | 兩項都勾＝請假＋補堂。要記成「改期」的話請在系統按「改期」 |
| 在系統裡按了「改期」（常規課或補堂） | 改期通知彈窗與課卡上按「改 GCal 舊事件（舊 → 新）」→ 打開 Calendar 上原本那個事件的編輯頁（沒同步過就開舊時段那一天）→ 把時間改成新的 → 儲存。不要另建新事件。Google 不支援預填既有事件，新時間要自己打（提示會寫明改成幾號幾點） | 還沒改：「本地已改期、Calendar 上還是舊時間」；改好就消失 | —（只是提示，不改本地） |
| 排補堂 | 新建事件，標題 `S001 Student 001 MU`（MU 可不寫），設好日期時間 | 手動新建 → 下拉選「作為補堂 ←（某日 L）」 | 補堂掛到那次請假、生成「補堂確認」 |
| 加一堂（不掛任何請假） | 同上 | 手動新建 → 「獨立加課」 | 多一堂 |
| 整堂取消、不補 | 刪掉事件 | Calendar 上沒有這堂 | 標請假（一對一記事假 L；小組記導師假 TL） |
| 取消已排的補堂 | **在系統按「取消補堂」。** 補堂事件已在 Calendar 的話，取消後系統會打開該事件（或那一天），請在 Calendar 把它刪掉。反過來在 Calendar 刪補堂事件，系統只會提議把補堂標請假，不是取消 | — | — |
| 確認出席 | **做不到。** | — | 系統「批量確認出席」 |
| 把系統排的補堂放進 Calendar | 系統補堂課卡按「加進 GCal」→ 選日曆 → 儲存 | 下次同步認得是同一堂，不會再列出 | — |
| 補堂已加進 Calendar，後來在系統改了時間 | **不要再按「加進 GCal」。** 課卡上的按鈕會變成「改 GCal 舊事件（舊時間 → 新時間）」：按它打開 Calendar 舊事件那一天，把那個事件拖／改到新時間 | 還沒改：「本地已改期、Calendar 上還是舊時間」（附「在 Calendar 打開」連結）；改好：不再列出 | —（只是提示，不會改本地） |

關於「改到另一天」：唯讀模式下系統是按「同一位學生、同一天」配對的，所以事件跨日拖走，系統在原日找不到、在新日多見一個。兩項都勾的結果是那天照樣上課、薪酬照算，只是記錄上是「請假＋補堂」而不是「改期」，訊息也會是請假確認＋補堂確認。想要乾淨的「改期」記錄，在系統課卡按「改期」，再按「加進 GCal」或自己在 Calendar 拖。

關於「兩邊都改了，聽誰的」：設定 → Google Calendar →「兩邊都改了時以哪邊為準」（預設 Google Calendar）。它只管「兩邊都有資訊、又不一樣」的情況——同一堂本地改了時間、Calendar 也被拖到第三個時間；或本地標了請假 `L`、Calendar 填的是病假 `SL`。只有一邊改了的一律跟那一邊：Calendar 拖了時間本地就跟；本地標了請假而 Calendar 沒填，唯讀模式就列出來請你去填（開了寫入的話同步會直接寫回）。

關於「系統裡改期，Calendar 怎麼跟」：系統會記住這堂在 Calendar 上原本的時間，所以同步時認得 Calendar 上舊時間那個事件就是這一堂——不會把它當成「手動新建」，也不會把系統裡的新時間當成「Calendar 上沒有」、更不會以 Calendar 為準把時間改回去。唯讀模式下系統不能替你改 Calendar，只會列出來提醒；開了寫入授權的話，「同步 GCal」會直接把原本那個事件改到新時間（不另建一個）。

關於「Calendar 上沒有這堂」：系統只在三個條件都成立時才敢這樣判斷——只看本月；只針對系統裡仍是「已排課」的堂（已請假、已上課的不管）；而且系統知道這本日曆屬於哪位導師（設定裡填了該導師的日曆 ID，或匯入 ICS 時選了導師）。不確定是誰的日曆時面板會說明並跳過這項，以免把別的導師的課整批誤判成取消。

## 5. 其他要注意的

- **全日事件**沒有時間，不能收編。補上開始時間。
- **每週重複事件**沒問題，同步時會逐次展開比對。
- **一位導師一本日曆**：事件在誰的日曆裡就算誰的課。放錯日曆＝系統在 A 的日曆找不到 A 的課（會提議請假），又在 B 的日曆多出一堂認不出的課。
- **匯入同一個 .ics 兩次不會重複**：事件 UID 固定，Google 依 UID 查重。
- **沒有 Google 授權也行**：Google Calendar 網頁 → 設定 → 匯入及匯出 → 匯出（會得到 zip，解壓後每本日曆一個 .ics）→ 系統總課表「匯入 ICS」→ 選這是哪位導師的日曆 → 上傳。規則和上面完全一樣，只是不用登入。

## 6. 每月的節奏

1. **月初**：系統「生成」當月課表 → 「導出 .ics」（自動一位導師一個檔）→ 每位導師把自己的檔匯入自己的 Google 日曆（Google Calendar 設定 → 匯入及匯出 → 匯入）。
2. **平時**：出席在系統批量確認；請假、補堂、同日改時間可以在 Calendar 按第 4 節做。
3. **每週同步一次**：總課表「同步 GCal」（或「匯入 ICS」），逐條勾選要套用的差異。
4. **同步之後**：系統生成的請假確認／補堂確認／改期通知在「發送中心」發給家長。
